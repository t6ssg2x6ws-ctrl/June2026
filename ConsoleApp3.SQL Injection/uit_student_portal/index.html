SQL Injection Protection Analysis

As implemented in dapperservice.cs, parameterized queries with Dapper eliminate SQL injection vulnerabilities by separating executable SQL code from user-supplied data parameters.

Vulnerable String Interpolation 
// UNSAFE (Commented out in dapperservice.cs):
$"select * from [dbo].[users] where username='{nae}' and password_hash='{psw}';"

Vulnerability Risk: Passing input like ' OR '1'='1 allows unauthorized authentication bypass.

Safe Parameterized Query (Active) 
// SAFE (Active implementation in dapperservice.cs):
"select * from [dbo].[users] where username=@username and password_hash=@password_hash",
new { username = nae, password_hash = psw }

Protection: SQL Server handles @username and @password_hash strictly as literal string parameters, disabling malicious syntax execution.
